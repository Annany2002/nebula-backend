## Create schema

**Endpoint:** `POST /api/v1/databases/:db_name/schema`

This endpoint uses the same request and creation behavior as [Create table](/api-reference/tables). Supply `table_name` and a nonempty `columns` or `schema` array; column-level and table-level foreign keys are supported. The server adds `id` and `created_at` columns automatically.

```bash
curl -X POST http://localhost:8080/api/v1/databases/mydb/schema \
  -H "Authorization: ApiKey <your-database-key>" \
  -H "Content-Type: application/json" \
  -d '{"table_name":"users","columns":[{"name":"name","type":"TEXT"}]}'
```

Successful creation or an existing table returns **201**:

```json
{
  "message": "Table 'users' created or already exists.",
  "db_name": "mydb",
  "table_name": "users"
}
```

An existing table is left unchanged; this endpoint does not compare or migrate its schema. Use [table alteration](/api-reference/tables#alter-table) to change it.

## Get schema

**Endpoint:** `GET /api/v1/databases/:db_name/tables/:table_name/schema`

Both endpoints accept the owner's JWT or an API key scoped to this database.

```bash
curl http://localhost:8080/api/v1/databases/mydb/tables/users/schema \
  -H "Authorization: ApiKey <your-database-key>"
```

The response wraps column names, types, and primary-key flags in `schema`:

```json
{
  "schema": [
    {"name":"id","type":"INTEGER","pk":true},
    {"name":"name","type":"TEXT","pk":false},
    {"name":"created_at","type":"TIMESTAMP","pk":false}
  ]
}
```

`pk` is a boolean on this endpoint. The current schema reader parses the stored `CREATE TABLE` statement; table-level constraint entries can also appear in its output. For SQLite column flags, default expressions, and foreign-key metadata, use the [schema diagram endpoint](/api-reference/diagram).

The records API uses the actual primary key, including renamed or text keys in tables created through SQL.

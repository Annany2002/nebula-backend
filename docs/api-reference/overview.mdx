# API Overview

Nebula provides a REST API for accounts, database management, schemas, records, SQL execution, inspection, and exports. All example requests use the local backend; replace its origin with your own deployment URL.

## Base URL

```
http://localhost:8080
```

## Authentication

Nebula supports two authentication methods:

<CardGroup cols={2}>
  <Card title="JWT Bearer Token" icon="key">

    ```
    Authorization: Bearer <token>
    ```
  </Card>
  <Card title="API Key" icon="lock">
    For database-scoped operations
    ```
    Authorization: ApiKey <key>
    ```

</CardGroup>

## Endpoints

### Public Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/ping` | Health check (returns "pong") |
| GET | `/health` | Server health status |
| POST | `/auth/signup` | Register new user |
| POST | `/auth/login` | Login and get JWT |

### Protected Endpoints (require authentication)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/v1/health` | Auth health check |
| GET | `/api/v1/user/:user_id` | Get user details |

### Database Management

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/v1/databases` | List databases |
| POST | `/api/v1/databases` | Create database |
| GET | `/api/v1/databases/:db_name` | Get database details |
| DELETE | `/api/v1/databases/:db_name` | Delete database |

Database listing, creation, and deletion require a JWT. Database details accept a JWT or a key scoped to that database.

### Account Profile (JWT only)

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/api/v1/account/user/me` | Get current profile |
| PUT | `/api/v1/account/user/me` | Update current profile |

### API Key Management (JWT only)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/v1/account/databases/:db_name/apikey` | Get API key info |
| POST | `/api/v1/account/databases/:db_name/apikey` | Create API key |
| DELETE | `/api/v1/account/databases/:db_name/apikey` | Delete API key |

### Schema & Tables

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/v1/databases/:db_name/schema` | Create table schema |
| GET | `/api/v1/databases/:db_name/tables/:table_name/schema` | Get schema |
| GET | `/api/v1/databases/:db_name/tables` | List tables |
| POST | `/api/v1/databases/:db_name/tables` | Create table |
| POST | `/api/v1/databases/:db_name/tables/:table_name/alter` | Alter table |
| DELETE | `/api/v1/databases/:db_name/tables/:table_name` | Delete table |

### Records (CRUD)

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/v1/databases/:db_name/tables/:table_name/records` | Create record |
| GET | `/api/v1/databases/:db_name/tables/:table_name/records` | List records |
| GET | `/api/v1/databases/:db_name/tables/:table_name/records/:record_id` | Get record |
| PUT | `/api/v1/databases/:db_name/tables/:table_name/records/:record_id` | Update record |
| DELETE | `/api/v1/databases/:db_name/tables/:table_name/records/:record_id` | Delete record |

### SQL, Inspection, and Exports

These endpoints accept a JWT or a key scoped to the selected database.

| Method | Endpoint | Reference |
| --- | --- | --- |
| POST | `/api/v1/databases/:db_name/sql` | [SQL execution](/api-reference/sql) |
| GET | `/api/v1/databases/:db_name/analytics` | [Analytics](/api-reference/analytics) |
| GET | `/api/v1/databases/:db_name/diagram` | [Schema diagram](/api-reference/diagram) |
| GET | `/api/v1/databases/:db_name/objects` | [Database objects](/api-reference/objects) |
| POST | `/api/v1/databases/:db_name/indexes` | [Create an index](/api-reference/objects#create-an-index) |
| DELETE | `/api/v1/databases/:db_name/indexes/:index_name` | [Drop an index](/api-reference/objects#drop-an-index) |

| GET | `/api/v1/databases/:db_name/export/sqlite` | [SQLite snapshot](/api-reference/exports) |

### Managed backups (owner JWT only)

Saved snapshots, history, verified downloads, deletion and restore into a new database are documented in the [managed backup API](/api-reference/backups). Snapshots survive deleting their source database; database-scoped API keys cannot manage them.

## Rate Limiting

API requests are rate-limited by IP address. If you exceed the limit, you'll receive a `429 Too Many Requests` response.

## Error Responses

Most API errors return JSON in this format:

```json
{
  "error": "Error message description"
}
```

Common status codes:

| Code | Description |
|------|-------------|
| 400 | Bad Request - Invalid input |
| 401 | Unauthorized - Missing/invalid auth |
| 403 | Forbidden - Insufficient permissions |
| 404 | Not Found - Resource doesn't exist |
| 409 | Conflict - Resource already exists |
| 429 | Too Many Requests - Rate limited |
| 500 | Internal Server Error |

# Database Management

Create, list, and delete databases. Each database is an isolated SQLite file.

<Note>
  Database management requires **user-scoped authentication** (JWT Bearer token). API keys cannot create or delete databases.
</Note>

## Create Database

Register a new database for the authenticated user.

**Endpoint:** `POST /api/v1/databases`

<ParamField body="db_name" type="string" required>
  Name for the new database (alphanumeric and underscores only)
</ParamField>

<RequestExample>
```bash cURL
curl -X POST http://localhost:8080/api/v1/databases \
  -H "Authorization: Bearer <your-jwt-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "db_name": "my_app_db"
  }'
```
</RequestExample>

<ResponseExample>
```json 201 Created
{
  "message": "Database registered successfully",
  "db_name": "my_app_db"
}
```

```json 409 Conflict
{
  "error": "Database already exists"
}
```
</ResponseExample>

## List Databases

Get all databases owned by the authenticated user.

**Endpoint:** `GET /api/v1/databases`

<RequestExample>
```bash cURL
curl http://localhost:8080/api/v1/databases \
  -H "Authorization: Bearer <your-jwt-token>"
```
</RequestExample>

<ResponseExample>

## Delete Database

Delete a database and all its data.

**Endpoint:** `DELETE /api/v1/databases/:db_name`

<ParamField path="db_name" type="string" required>
  Name of the database to delete
</ParamField>

<RequestExample>
```bash cURL
curl -X DELETE http://localhost:8080/api/v1/databases/my_app_db \
  -H "Authorization: Bearer <your-jwt-token>"
```
</RequestExample>

<ResponseExample>
```json 404 Not Found
{
  "error": "Database not found"
}
```
</ResponseExample>

Successful deletion returns **204 No Content**. Database list and detail responses include `apiKeyPrefix` only when a key exists; they never include a full API key.

<Warning>
  Deleting a database **permanently removes** all tables, records, and associated API keys. This action cannot be undone.
</Warning>

## Database Exports

- `GET /api/v1/databases/:db_name/export/sqlite` downloads a consistent standalone `.db` snapshot, including committed data in the WAL.
- `GET /api/v1/databases/:db_name/export/sql` returns `{ "sql": "..." }`. The dump reads schema and data in one transaction and preserves SQLite text, BLOB, timestamp and NULL values, plus indexes, views and triggers.

Both endpoints accept the owner's JWT or an API key scoped to that database.

## SQL Isolation

`POST /api/v1/databases/:db_name/sql` accepts `{ "query": "..." }` for SQL within the selected database. Tenant connections reject `ATTACH`, `DETACH`, filesystem SQL functions, extension loading and directory/writable-schema pragmas. `VACUUM` and `VACUUM INTO` also use SQLite's attach operation and are unavailable through tenant connections. Rejected SQL returns **400 Bad Request**.

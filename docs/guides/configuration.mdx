# Configuration

Copy `.env.example` for local development or supply settings through the process environment. The configuration loader reads `.env` outside `APP_ENV=production`. Keep credentials and runtime data out of source control.

## Core settings

| Variable                  | Default                       | Purpose                                           |
| ------------------------- | ----------------------------- | ------------------------------------------------- |
| `APP_ENV`                 | Unset                         | Set to `production` for production configuration  |
| `SERVER_PORT`             | `8080`; `8085` in production  | HTTP listen port, from 1 to 65535                 |
| `JWT_SECRET`              | Required                      | Strong, unique JWT signing secret                 |
| `JWT_EXPIRATION_HOURS`    | `24`                          | Positive JWT lifetime in hours                    |
| `DATABASE_DIRECTORY`      | `data`                        | Metadata, tenant databases and retained snapshots |
| `DATABASE_DIRECTORY_FILE` | `metadata.db`                 | Metadata database filename                        |
| `ALLOWED_ORIGINS`         | All origins when empty or `*` | Space-separated allowed frontend origins          |

Generate a signing secret, then store it in your environment or deployment secrets:

```bash
openssl rand -base64 32
```

### Account email and password recovery

Email verification is opt-in. `EMAIL_VERIFICATION_ENABLED=false` preserves the existing registration flow. Password recovery has a separate `PASSWORD_RESET_ENABLED` flag, also disabled by default. SMTP credentials are required when either feature is enabled; neither feature requires them when both flags are false. Enabling either feature validates every required mail setting at startup; insecure or incomplete configuration prevents the server from starting.

| Variable                         | Default    | Purpose and requirements                                                                                                       |
| -------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `EMAIL_VERIFICATION_ENABLED`     | `false`    | Set to `true` after completing the rollout below                                                                               |
| `PASSWORD_RESET_ENABLED`         | `false`    | Enable reset requests and token consumption independently of signup verification                                               |
| `PASSWORD_RESET_TTL_MINUTES`     | `30`       | Integer from 5 to 120; reset-link lifetime                                                                                     |
| `APP_PUBLIC_URL`                 | None       | Frontend HTTPS origin; no path, query, fragment, or embedded credentials. HTTP allowed only for `localhost` and `127.0.0.1`    |
| `EMAIL_VERIFICATION_TTL_MINUTES` | `30`       | Integer from 5 to 120                                                                                                          |
| `SMTP_HOST`                      | None       | SMTP server hostname                                                                                                           |
| `SMTP_PORT`                      | `587`      | Port from 1 to 65535                                                                                                           |
| `SMTP_USERNAME`                  | None       | Authentication username                                                                                                        |
| `SMTP_PASSWORD`                  | None       | Authentication password; configure through environment secrets                                                                 |
| `SMTP_FROM`                      | None       | Plain sender mailbox; display names are not accepted                                                                           |
| `SMTP_TLS_MODE`                  | `starttls` | `starttls` for STARTTLS, or `tls` for implicit TLS (commonly port 465)                                                         |
| `SMTP_CA_FILE`                   | None       | Optional PEM CA bundle for private SMTP certificates; extends system trust without disabling certificate/hostname verification |

SMTP authentication is sent only over TLS with verified certificates. Plaintext delivery and STARTTLS downgrade are rejected. Each SMTP conversation has a 10-second deadline and respects request cancellation. Mail settings reject header line breaks; credentials and message tokens are not logged by the delivery adapter.

<Steps>
  <Step title="Deploy compatible clients">
    Deploy the frontend `/verify-email` page, pending-account signup/login
    handling, and confirmed email-change flow. Update SDK callers to handle
    verification statuses and `202` email-change responses. Leave verification
    disabled during this stage.
  </Step>
  <Step title="Configure and test SMTP">
    Set a trusted frontend origin and your provider's SMTP credentials in the
    deployment environment. Confirm the sender mailbox is authorized with your
    provider. Test signup, resend, expired links, and an email change against a
    staging deployment.
  </Step>
  <Step title="Enable new-account verification">
    Set `EMAIL_VERIFICATION_ENABLED=true` and restart only the backend. Newly
    registered accounts must verify before login or protected API access.
    Existing accounts remain accessible without falsely reporting that their
    addresses are verified.
  </Step>
</Steps>

Verification requirements, token hashes, session versions, and send limits persist in the metadata database. Turning delivery off does not unlock already restricted accounts or bypass confirmation for their address changes; existing valid links can still be confirmed. Preserve the metadata database during rollout and rollback.

Resend work uses four bounded in-process workers rather than a durable queue. A successful acknowledgement is not a delivery guarantee; clients can retry after interrupted delivery. Signup and resend share 10 requests per client IP per 15 minutes, and enabled recovery routes share that public budget. Account sending across verification and recovery is limited to five requests per hour with a 60-second cooldown. In the existing tunnel deployment, client addresses are accepted from `CF-Connecting-IP` only when the connection comes from a loopback Cloudflare connector; other proxy topologies share the proxy's request budget unless adapted explicitly.

### Password recovery rollout

Deploy the backend endpoints and frontend `/forgot-password` and `/reset-password` routes before setting `PASSWORD_RESET_ENABLED=true`. Configure the same validated SMTP transport and `APP_PUBLIC_URL` used by verification. Recovery can run with `EMAIL_VERIFICATION_ENABLED=false`; enabling recovery does not restrict new signups or claim verification for existing addresses.

`PASSWORD_RESET_TTL_MINUTES` defaults to 30 and accepts 5–120. Turning recovery off disables both requests and consumption. Reset success revokes existing JWT sessions and pending email-change/verification links, while preserving database API keys and existing verification/suspension policy. Notification email is best effort after the commit. See [password recovery](/api-reference/password-recovery) for the canonical contract and uncertain-write handling.

For local testing, `./scripts/dev-email.sh` enables both flags and captures mail in an isolated Mailpit inbox. No production credentials or domain are needed.

### CORS

Set explicit frontend origins for public deployments. CORS is a browser policy, not authentication or a firewall.

```bash
ALLOWED_ORIGINS=http://localhost:3000 https://app.example.com
```

## Example .env File

```bash
# Server
SERVER_PORT=8080

# Authentication
JWT_SECRET=change-this-to-a-very-long-and-secure-random-string
JWT_EXPIRATION_HOURS=24

# Enable only after SMTP and the frontend verification flow are ready.
EMAIL_VERIFICATION_ENABLED=false
PASSWORD_RESET_ENABLED=false
PASSWORD_RESET_TTL_MINUTES=30
APP_PUBLIC_URL=http://localhost:3000
EMAIL_VERIFICATION_TTL_MINUTES=30
SMTP_HOST=
SMTP_PORT=587
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM=
SMTP_TLS_MODE=starttls
SMTP_CA_FILE=

# CORS
ALLOWED_ORIGINS=http://localhost:3000 http://localhost:5173
```

## Local setup and deployment

1. Copy `.env.example` to `.env` for development.
2. Set a unique `JWT_SECRET` and local `ALLOWED_ORIGINS`.
3. Configure SMTP only when enabling account mail features.

For isolated email testing, run `./scripts/dev-email.sh`, or `./dev.sh --email` in the three-repository workspace. The runner captures mail at `http://localhost:8025`, enables verification and recovery, and does not change normal local accounts, `.env` or system certificate trust.

On the existing VPS, explicitly use `SERVER_PORT=8085`. Preserve metadata, tenant data, snapshots and environment files during deployment. Restart only the backend when preserving a running Cloudflare Quick Tunnel URL. See [deployment](/guides/deployment) for storage and process constraints.

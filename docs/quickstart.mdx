# Quick start

Use the Go version in `go.mod` and a C compiler for the SQLite CGO driver, or run the backend through Docker.

## Run with Go

```bash
git clone https://github.com/Annany2002/nebula-backend.git
cd nebula-backend
cp .env.example .env
# Set a strong development JWT_SECRET and your frontend ALLOWED_ORIGINS.
make run
```

The API listens on `http://localhost:8080`. Verification and password recovery are disabled by default; neither requires SMTP credentials while disabled.

```bash
curl http://localhost:8080/ping
# pong
curl -i http://localhost:8080/health
# HTTP 200 with an empty body
```

## Run with Docker

```bash
docker compose up --build backend
```

The API binds to port 8080 using the example environment. The optional Compose documentation service uses port 3000, which conflicts with the frontend's default port. Start it separately or use `npx mint@4.2.984 dev --port 3002` from `docs/`. Configure production ports and persistent storage explicitly; see [deployment](/guides/deployment).

## Test account email locally

Stop any backend already using port 8080, then run:

```bash
./scripts/dev-email.sh
```

This starts the backend with verification and password recovery enabled, isolated accounts and an authenticated TLS Mailpit inbox at `http://localhost:8025`. It does not edit `.env`, normal local data or system trust, and it captures mail instead of sending it externally.

Start the [Nebula frontend](https://github.com/Annany2002/nebula-frontend) on port 3000 with `VITE_BACKEND_URL=http://localhost:8080`. In a workspace containing all three repositories, `./dev.sh --email` starts the API, frontend and inbox together.

Sign up, confirm the captured email, sign in, then choose **Forgot password?** to request and complete a reset. Reopen the original email link after refreshing a cleaned confirmation/reset page. See [password recovery](/api-reference/password-recovery) for expiry, session revocation and retry behavior.
